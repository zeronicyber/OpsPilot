## Investigation Report for INC008381005

### Incident Summary
- **Incident ID:** INC008381005
- **Status:** Resolved
- **Summary:** Metadata pool exhaustion caused authentication and workspace session failures due to connection saturation.

---

### Evidence Collected

#### **Log Evidence**
- **Connection Pool Saturation (09:02:16 - 09:14:21):**
  - Pool utilization reached **92% to 99%**, with pending requests increasing from **9 to 37**.
  - Metadata repository request timeouts occurred (e.g., `id=78142`, `id=78191`).
  - Authentication queue grew to **31 requests**.
  - Workspace session creation failures and timeouts were observed.

- **Authentication and Workspace Failures (09:15:07 - 09:27:02):**
  - Authentication token validation failed for users `jsmith`, `akumar`, and `mgarcia`.
  - Workspace session creation failed for requests `WS55281`, `WS55294`, and `WS55302`.
  - **63% of workspace launches were rejected**, with **71 requests queued**.
  - Connection pool fully saturated (**99%**), leading to **12 new requests rejected**.

- **Resolution Phase (09:27:02 - 09:33:02):**
  - Root cause identified as **metadata pool exhaustion**.
  - Restart of metadata services (`CHG004991`) initiated after draining connections.

---

#### **Knowledge Base Article**
- **KB Reference:** KB-1023.md
- **Title:** Metadata Service Connection Saturation
- **Root Cause:** Metadata Server connection pool exhaustion due to stale or long-running connections.
- **Resolution Steps:**
  1. Stop new workspace launch traffic or place the affected scheduler route in maintenance mode.
  2. Clear stale client connections using the approved SAS administration procedure.
  3. Restart the Metadata Server under an approved change if the connection pool cannot be safely drained.
  4. Verify the Metadata service binds to port 8561 and the repository integrity check passes.
  5. Reconnect authentication services and verify Object Spawner registration on every Grid node.
  6. Gradually release traffic after confirming stability.

- **Validation Checklist:**
  - Metadata service health probe and repository login succeed.
  - Connection pool utilization below 70% and waiters at zero.
  - Authentication succeeds for a new test user.
  - Object Spawner creates a Workspace Server session.
  - A user can launch and execute a SAS workspace session.
  - No new metadata timeouts occur during the monitoring window.

---

## Root Cause Confidence

**Root Cause Candidates**
1. **Metadata connection pool exhaustion due to stale or long-running connections** - 50%
2. **High volume of authentication requests overwhelming the metadata repository** - 30%
3. **Workspace session creation failures due to lack of available pooled connections** - 20%

**Selected Cause:**
**Metadata connection pool exhaustion due to stale or long-running connections**

---

## Recovery Plan

### **Immediate Actions**
1. **Stop Traffic:**
   - Place the affected scheduler route in maintenance mode to prevent new workspace launches.
2. **Clear Stale Connections:**
   - Use the approved SAS administration procedure to identify and clear stale client connections.

### **Restart and Validation**
3. **Restart Metadata Server:**
   - Execute restart under approved change `CHG004991` if the connection pool cannot be safely drained.
4. **Verify Service Binding:**
   - Confirm the Metadata service binds to port 8561 and the repository integrity check passes.

### **Reconnection and Monitoring**
5. **Reconnect Services:**
   - Reconnect authentication services and verify Object Spawner registration on every Grid node.
6. **Gradual Traffic Release:**
   - Launch a canary Workspace Server session, then release traffic gradually.

### **Validation**
- Ensure connection pool utilization is below **70%** and waiters are at **zero**.
- Verify authentication and workspace session creation succeed for test users.
- Monitor for new metadata timeouts during the validation window.

**KB Source:** [KB-1023.md](KB-1023.md) - *Metadata Service Connection Saturation*
