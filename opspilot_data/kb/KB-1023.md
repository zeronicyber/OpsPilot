# KB-1023 Metadata Service Connection Saturation

## Incident Mapping

- **Incident:** INC008381005
- **Service:** SAS Grid Platform
- **Priority:** P1

## Problem Description

SAS Grid users cannot launch Workspace Server sessions when the SAS Metadata Server connection pool is exhausted. Authentication and Object Spawner requests queue behind unavailable metadata connections, producing cascading workspace launch failures.

## Symptoms

- Workspace launch requests time out or are rejected.
- Metadata repository requests report connection timeouts.
- Authentication token validation fails for new sessions.
- Object Spawner cannot create Workspace Server sessions.
- Existing users may remain connected while new users are affected.

## Root Cause

The Metadata Server connection pool is exhausted by stale or long-running connections. Pool utilization reaches the configured maximum, preventing authentication and Object Spawner metadata requests from acquiring a connection.

## Diagnostic Procedure

1. Check `sas-metadata-01` service state and listener port 8561.
2. Review pool metrics and confirm utilization, active connections, waiters, and rejected requests:
   ```text
   Connection pool utilization > 95%
   Metadata repository request timeout
   ```
3. Correlate metadata timeouts with authentication token validation failures in the auth log.
4. Review Object Spawner logs on `sas-grid-01` through `sas-grid-03` for session creation failures.
5. Test repository responsiveness with a service-account metadata login before attempting a workspace launch.
6. Preserve pool metrics, failed user IDs, request IDs, and timestamps for the incident record.

## Resolution Procedure

1. Stop new workspace launch traffic or place the affected scheduler route in maintenance mode.
2. Identify and clear stale client connections using the approved SAS administration procedure.
3. Restart the Metadata Server under an approved change if the pool cannot be safely drained.
4. Confirm the service binds to port 8561 and the repository integrity check passes.
5. Reconnect authentication services and verify Object Spawner registration on every Grid node.
6. Launch a canary Workspace Server session, then release traffic gradually.

## Validation Steps

- [ ] Metadata service health probe and repository login succeed.
- [ ] Connection pool utilization is below 70% and waiters are zero.
- [ ] Authentication succeeds for a new test user.
- [ ] Object Spawner creates a Workspace Server session.
- [ ] A user can launch and execute a SAS workspace session.
- [ ] No new metadata timeouts occur during the monitoring window.

## Prevention Recommendations

- Alert at 70%, 85%, and 95% pool utilization.
- Monitor stale connection age and authentication queue depth.
- Review client connection release behavior after Grid upgrades.
- Maintain a tested Metadata Server restart and connection-drain procedure.

## Estimated Recovery Time

30-45 minutes, depending on whether a controlled connection drain or full Metadata Server restart is required.

## Escalation Guidelines

Escalate immediately to the SAS platform owner for a P1 user-wide impact. Engage database or infrastructure support if repository checks fail after restart, or if pool exhaustion recurs within the monitoring window.
