# KB-1111 Python Batch Scoring Job Failure

## Incident Mapping

- **Incident:** INC008381111
- **Service:** Python Analytics Platform
- **Priority:** P2

## Problem Description

A scheduled Python scoring job aborts before processing records because the batch worker cannot retrieve its model from the unavailable model registry.

## Symptoms

- Batch scoring aborts during model lookup.
- Registry requests show increasing latency and connection retries.
- Model lookup returns timeout or HTTP 504 errors.
- Zero records are scored and downstream jobs remain held.

## Root Cause

The model registry API cannot acquire database connections and stops responding within the batch timeout. The worker cannot download the required model artifact, so scoring is safely aborted before output is written.

## Diagnostic Procedure

1. Record job ID, batch server, model name, start time, and execution duration.
2. Test registry health from `batch-scorer-04`:
   ```bash
   curl -sk -o /dev/null -w '%{http_code} %{time_total}\n' https://model-registry-01/health
   ```
3. Query the exact model version and inspect HTTP status, response time, and checksum.
4. Review `model-registry-01` logs for database pool exhaustion, request queue depth, and API 5xx responses.
5. Confirm the failed worker did not write partial scoring output before holding downstream dependencies.

## Resolution Procedure

1. Hold the failed job and downstream jobs to prevent duplicate or partial results.
2. Restart the model registry service under the approved change record.
3. Confirm registry health returns HTTP 200 and the database pool is below its saturation threshold.
4. Download the exact model artifact to `batch-scorer-04` and verify its manifest checksum.
5. Re-run the scoring process with a new execution ID linked to the failed job.
6. Validate row counts, schema, checksum, and execution duration before releasing downstream jobs.

## Validation Steps

- [ ] Registry health and model lookup return HTTP 200.
- [ ] Model download and checksum validation succeed.
- [ ] Batch rerun processes the expected input row count.
- [ ] Output is complete and no partial file is promoted.
- [ ] Execution duration is within the normal baseline.
- [ ] Downstream jobs are released only after output validation.

## Prevention Recommendations

- Alert on registry database pool utilization and API latency.
- Cache approved model artifacts on workers with checksum validation.
- Add a preflight model lookup before consuming batch input.
- Retain failed and rerun job IDs in scheduler audit records.

## Estimated Recovery Time

20-40 minutes for registry restart, artifact verification, and controlled rerun.

## Escalation Guidelines

Escalate to model platform engineering if registry health does not recover after restart, the model manifest is missing, or multiple scheduled jobs are blocked.
