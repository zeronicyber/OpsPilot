# KB-1044 SAS Management Console Latency

## Incident Mapping

- **Incident:** INC008381021
- **Service:** SAS Grid Platform
- **Priority:** P3

## Problem Description

SAS Management Console remains available but opens slowly and intermittently freezes while metadata cache synchronization completes. The condition affects console startup and metadata browsing without indicating a full SAS service outage.

## Symptoms

- Console startup takes significantly longer than the baseline.
- Metadata queries and folder browsing show elevated response times.
- Administrators see intermittent freezes while authorization or repository data loads.
- Existing console sessions remain usable after delayed responses.

## Root Cause

Metadata cache synchronization delays cause repeated repository reads and stale-cache refreshes. The resulting metadata request queue increases response time for SAS Management Console startup and browse operations.

## Diagnostic Procedure

1. Record console startup time, user ID, host, operation, and request latency.
2. Check `sas-metadata-01` request queue, repository response time, and cache synchronization status.
3. Compare cache refresh timestamps with the first slow console probe.
4. Review Management Console and metadata logs for retries, authorization delays, and repository request timeouts.
5. Confirm port 8561 remains reachable and that health probes return success; distinguish latency from service refusal.
6. Check whether the delay is isolated to one console host or reproduced on `sas-smc-02` and a second administrator workstation.

## Resolution Procedure

1. Allow the active cache synchronization cycle to complete unless it is demonstrably stuck.
2. If synchronization is stuck, perform the approved metadata cache refresh or restart the affected console client.
3. Reduce nonessential repository browse traffic while synchronization catches up.
4. Restart the console service only after confirming the metadata server itself is healthy.
5. Re-run startup and folder-browse probes from multiple console hosts.

## Validation Steps

- [ ] Management Console startup returns to the agreed baseline.
- [ ] Metadata browse and authorization requests complete without retries.
- [ ] Repository response latency remains stable for at least 15 minutes.
- [ ] No metadata connection refusals or repository errors occur.
- [ ] Existing users can navigate without intermittent freezes.

## Prevention Recommendations

- Alert on cache synchronization age and metadata response percentiles.
- Schedule large metadata refresh operations outside administrator peak hours.
- Track console startup latency by host and release version.
- Keep cache synchronization and repository maintenance procedures documented.

## Estimated Recovery Time

15-30 minutes when synchronization completes normally; longer if a stuck cache requires administrative refresh.

## Escalation Guidelines

Escalate to SAS metadata support if latency exceeds the P3 threshold for 30 minutes, affects multiple console hosts, or is accompanied by repository errors or connection failures.
