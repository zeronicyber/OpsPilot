# KB-0944 Missing Input File During SAS Batch Processing

## Incident Mapping

- **Incident:** INC008380944
- **Service:** SAS Batch Processing
- **Priority:** P3

## Problem Description

The scheduled `nightly_claims` SAS batch starts but aborts during input validation because the upstream ETL process did not deliver the date-specific source file.

## Symptoms

- The scheduled batch fails immediately before reading records.
- Input validation reports a missing path under `/sasdata/in`.
- `claims_load.sas` returns code 2 and no output dataset is written.
- Downstream scheduler dependencies remain held.

## Root Cause

The upstream vendor ETL transfer did not deliver `claims_YYYYMMDD.csv` before the batch schedule. The SAS process and batch host are healthy; the required source file is absent or incomplete.

## Diagnostic Procedure

1. Capture batch name, job ID, SAS process, expected date, and input path.
2. Verify the path and permissions on `sas-batch-02`:
   ```bash
   ls -l /sasdata/in/claims_$(date +%Y%m%d).csv
   df -h /sasdata/in
   ```
3. Check the upstream ETL and SFTP delivery audit for transfer status, byte count, checksum, and final rename.
4. Confirm no partial file is visible and that the service account can read the completed file.
5. Check scheduler dependency state before authorizing a rerun.

## Resolution Procedure

1. Hold `nightly_claims` and downstream jobs; notify operations and the ETL owner.
2. Restore or retransmit the source file from the upstream vendor process.
3. Verify size, checksum, permissions, and final date-specific filename.
4. Authorize a controlled rerun of `claims_load.sas` and `claims_transform.sas`.
5. Validate output dataset row counts and checksum before releasing dependencies.

## Validation Steps

- [ ] Source file exists at the expected path and is checksum-verified.
- [ ] SAS processes return code 0 with no input validation errors.
- [ ] Expected records are read and transformed.
- [ ] `claims_summary.sas7bdat` is present and readable.
- [ ] Downstream jobs are released after output controls pass.

## Prevention Recommendations

- Add an upstream delivery SLA alert before the SAS batch start time.
- Use a readiness marker and atomic file rename for vendor deliveries.
- Configure scheduler dependencies on file readiness, not only elapsed time.
- Alert on missing, partial, or checksum-failing source files.

## Estimated Recovery Time

20-45 minutes after the upstream file is retransmitted; rerun duration depends on input volume.

## Escalation Guidelines

Escalate to the ETL owner and SAS operations lead when the file misses the delivery SLA, retransmission fails, or downstream reporting deadlines are at risk.
